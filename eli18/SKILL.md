# eli18

把用户给出的主题讲给一位有高中基础、但没有该领域专业知识的读者。目标是让读者理解它为什么这样工作，并能用所学解释一个具体例子。

主题取自用户当前请求；支持 `/eli18 <主题>` 和 `$eli18 <主题>`。没有主题时再询问。

## 解释方式

- 假设读者理解基础代数、函数、概率和常见科学概念。需要其他前置知识时，先用几句话补齐，不假设读者学过微积分或专业课程。
- 开头直接说明它是什么、解决什么问题，再顺着因果关系解释如何运作。不要只给结论或堆术语。
- 保留必要的正式术语，首次出现时用日常语言说明含义。不要为了通俗而改掉术语或省略关键条件。
- 选一个读者熟悉的具体例子，跟着机制逐步算或走一遍。类比有帮助时再用，并说明它在哪一点不再适用，避免把类比当作事实。
- 公式能帮助理解时就用，解释符号、单位和每一步的含义；优先用高中数学。主题不需要公式时，不强行加入。
- 点明会影响结论的适用条件和常见误解。区分事实、简化模型与尚未确定的说法；简化表达不能改变原理。
- 默认跟随用户语言，平等、直接地交流，不用幼儿口吻、夸奖式开场或装饰性比喻。篇幅随主题调整，不强制凑段落或知识点数量。

## HTML 图解

默认交付可直接打开的 HTML 文件，并在回复中附上文件链接和简短说明。用户明确要求纯文字或其他格式时，遵从用户选择。

- 用示意图、流程图、对比图或坐标图呈现主题中最值得看清的关系。图要有标签，箭头说明方向，坐标注明单位；不加只作装饰的图片。
- 图旁保留足够的文字，讲清机制和例子的推理过程，不沿用“五岁儿童版”的极少文字要求。
- 只有在交互确实帮助理解时才添加滑块或按钮，例如改变参数观察结果；显示当前数值和含义。
- 优先使用内联 CSS、SVG 和必要的 JavaScript，让文件无需构建或外部依赖即可打开。适配手机宽度，保证文字和图例可读。
- 交付前检查 HTML 能打开、图文对应、公式和例子一致；有交互时检查它确实改变对应结果。无法实际打开验证时如实说明。
